# writing-review 스킬

[`writing-guide.md`](./writing-guide.md)를 주 기준으로, [`fluent-korean.md`](./fluent-korean.md)를 보조 기준으로 문서를 검증하고 수정합니다. 신규 작성 시에는 같은 지침을 작성 기준으로 적용합니다.

**규칙의 원천은 두 지침 파일입니다.** writing-guide.md는 문장·한국어·문서 구성 규칙을, fluent-korean.md는 문장 성분 생략과 어휘 선택 같은 문장 명료성 규칙을 담습니다. 이 스킬은 절차와 도구만 정의하고, 규칙 자체는 지침 원문을 그대로 따릅니다. 두 지침이 충돌하면 writing-guide.md를 우선합니다. 규칙이 바뀌면 지침만 고치면 됩니다.

## 모드 판별

| 요청 | 모드 | 산출물 |
|---|---|---|
| "점검해줘", "검증해줘", "지침에 맞는지 봐줘" | **검증** | 위반 보고(수정하지 않습니다) |
| "고쳐줘", "다듬어줘", "지침대로 수정해줘" | **수정** | 수정된 문서 + 변경 요약 |
| "지침대로 작성해줘" | **작성** | 지침을 기준으로 삼은 신규 문서 |

요청이 모호하면 검증 모드로 시작해 보고까지만 하고, 수정 여부를 묻습니다. 이 스킬은 글의 문장·구성 품질을 다룹니다. 문서에 담을 내용을 조사하거나 목차를 정하는 일은 다루지 않습니다.

## Step 1: 준비

1. `writing-guide.md` 전체를 Read로 로드합니다. 1부(문장 단위), 2부(한국어 특화), 3부(문서 구성)가 점검 기준입니다.
2. `fluent-korean.md` 전체를 Read로 로드합니다. 문장 단위(성분 생략, 문장 끝맺음)와 구 단위(조사·어미, 한자어, 비유적 어휘, 엠대시)가 보조 점검 기준입니다. 요약본으로 대체하지 않습니다.
3. 대상 문서를 전체 Read합니다. 일부만 읽고 점검하지 않습니다.
4. 문서 유형을 판별해 적용 범위를 정합니다.
   - **구성이 있는 문서**(PRD, TDD, 분석 문서, 운영 문서 등): 1·2·3부 전체 + 지침의 "작성 후 점검 목록" + fluent-korean.md 전체.
   - **짧은 본문**(PR 본문, 이슈 설명 등): 1·2부 중심 + fluent-korean.md 전체. 3부는 "근거 → 사실 → 해석 → 판단" 전개와 어미 구분만 적용합니다.
   - **짧은 제목류**(Jira 제목, PR 제목): 명사형 허용 규칙(2부)만 봅니다.

## Step 2: 기계 점검 (후보 검출)

정규식으로 잡을 수 있는 위반 후보를 먼저 걸러냅니다. 아래 스크립트를 대상 파일에 실행합니다. **결과는 후보일 뿐이므로, 원문을 읽고 실제 위반인지 판단한 것만 보고합니다.** 코드 블록과 표 안은 오탐이 많은 구간이니 특히 주의합니다.

```python
import re, sys

path = sys.argv[1]
text = open(path, encoding='utf-8').read()

PATTERNS = [
    ('이중 피동',    r'되어진|불려진|보여지|쓰여지|잊혀진'),
    ('번역투',      r'에 대하여|에 대한 |를 통하여|을 통하여|에 있어서|하는 것을 가능하게|를 가지고 있|을 가지고 있'),
    ('상대 시점',    r'최근에|지난달|지난주|얼마 전|현재로서는'),
    ('과잉 진행형',  r'하고 있는 중|되고 있는 중'),
    ('겹괄호',      r'\([^()]*\([^()]*\)[^()]*\)'),
    ('엠대시',      r'—'),
]

fence = False
plain_lines = []
for i, line in enumerate(text.split('\n'), 1):
    if line.strip().startswith('```'):
        fence = not fence
        continue
    if fence:
        continue
    # 마크다운 링크는 텍스트만 남깁니다. 링크 괄호가 겹괄호로 오탐되는 것을 막습니다.
    line = re.sub(r'\[([^\]]*)\]\([^)]*\)', r'\1', line)
    for name, pat in PATTERNS:
        for m in re.finditer(pat, line):
            print(f'{path}:{i} [{name}] …{line[max(0,m.start()-15):m.end()+15]}…')
    # 문장 길이: 어절 30개 초과 문장(설명문 기준 25어절의 여유치)
    for sent in re.split(r'(?<=다\.)\s', line):
        if len(sent.split()) > 30:
            print(f'{path}:{i} [긴 문장 {len(sent.split())}어절] {sent[:40]}…')
    # 어투: 지침은 "~습니다"체이므로 "~다." 평서체 종결을 후보로 올립니다
    if re.search(r'(?<!니)다[.!?)]', line):
        plain_lines.append(i)

if plain_lines:
    shown = ', '.join(map(str, plain_lines[:10]))
    more = f' 외 {len(plain_lines) - 10}곳' if len(plain_lines) > 10 else ''
    print(f'{path} [평서체 종결 {len(plain_lines)}줄] {shown}{more}')
```

## Step 3: 정독 점검 (기계로 못 잡는 항목)

지침을 옆에 두고 문서를 처음부터 읽으며 아래 축을 점검합니다. 위반마다 **위치(섹션·줄), 어긴 규칙(지침의 절 이름), 원문, 수정안**을 기록합니다.

- **용어 통일(1부):** 같은 대상을 두 가지 이상 이름으로 부르는 곳. 문서 안에서 등장 표기를 모아 비교합니다.
- **문장 구조(1부):** 한 문장에 지시·주제 두 개 이상, 명사 3연쇄 초과, 수식어와 대상의 거리, 조건과 동작의 순서.
- **주체 명확성(2부):** 시스템 동작과 사람 동작이 섞이는 문장에서 주어 생략.
- **사실·추정 어미(3부):** 근거 없이 단정한 곳, 추정인데 추정 어미가 없는 곳, 한 문장에 사실과 추정이 섞인 곳. **어미를 고칠 때는 근거를 확인합니다. 표현만 바꿔 추정을 사실로 승격하지 않습니다.**
- **전개 순서(3부):** 근거(데이터·다이어그램) 없이 해석부터 시작하는 절, 결론과 다음 액션이 섞인 마무리.
- **수치 3요소(3부):** 단위, 기준일, 비교 대상이 빠진 수치.
- **강조 남용(3부):** 한 문단에 볼드 세 군데 이상.
- **목록 형태(2부):** 한 목록 안에서 종결 형태가 섞인 항목.
- **성분 생략(fluent-korean 문장 1):** 목적어·대상·조건이 빠져 문장만 보고는 무엇을 가리키는지 알 수 없는 곳, "~의"로 성분을 뭉뚱그린 곳.
- **문장 끝맺음(fluent-korean 문장 2):** 본문 문장이 명사구, 부사구, 연결어미로 끝나는 곳. 제목과 목록 항목은 제외합니다.
- **어휘 선택(fluent-korean 구 2·3):** 조사 없이 한자어를 이어 붙인 곳, 일반 어휘 자리에 비유적 어휘를 쓴 곳.
- **(구성이 있는 문서) 작성 후 점검 목록:** 지침 끝의 항목을 그대로 확인합니다.

## Step 4: 보고 또는 수정

**검증 모드**: 다음 형식으로 보고하고 끝냅니다.

| 위치 | 규칙 | 원문 | 수정안 |
|---|---|---|---|
| 시스템 구조, 42행 | 2부 번역투 | 성능에 대한 개선을 통하여 | 성능 개선으로 |

- 위반이 없으면 "지침 위반 없음"과 함께 점검한 축을 요약합니다.
- 오탐 가능성이 있는 항목은 "판단 필요"로 분리해서 보고합니다.

**수정 모드**: 다음 원칙으로 고칩니다.

- **의미를 바꾸지 않습니다.** 사실 관계, 수치, 링크, 사실/추정의 구분은 그대로 유지합니다. 표현만 다듬습니다.
- **문장 단위로 최소한만 고칩니다.** 문제없는 문장은 건드리지 않고, 문서 전체를 다시 쓰지 않습니다.
- 고친 뒤 Step 2 스크립트를 다시 실행해 잔여 후보가 없는지 확인합니다.
- 변경 요약을 규칙 축별 건수와 대표 예시(수정 전 → 수정 후)로 보고합니다.

**작성 모드**: 쓰기 전에 지침의 해당 부(문서 유형에 따라 1·2부 또는 전체)를 로드하고, 초안 완성 후 Step 2~3을 자기 점검으로 한 번 돌립니다.

## 주의사항

- 인용문, 코드, 명령어, 로그, 리소스명은 수정 대상이 아닙니다. 원문 그대로 둡니다.
- 대화 출력 스타일과 이 지침은 별개입니다. 출력 스타일은 대화 문장에, 이 스킬은 문서 파일에 적용합니다. 문서 안에서 두 기준이 충돌하면 writing-guide.md를 따릅니다.
