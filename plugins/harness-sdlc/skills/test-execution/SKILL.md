# Test Execution — 테스트 실행 및 리포팅

## 목적

구현이 실제로 동작하는지 증명하고, **정직하게 보고**한다.
테스트 작성은 구현 에이전트의 책임이고, 실행과 보고가 이 스킬의 범위다.

## 최우선 원칙

> **실행하지 않은 것을 실행했다고 보고하지 않는다.**

환경 문제로 실행 불가한 영역은 "미실행"으로 명시한다.
미실행을 통과로 보고하는 것은 이 하네스에서 가장 심각한 위반이다 —
이후 모든 판정이 거짓 위에 서게 된다.

## 절차

### 1. 실행 명령 파악

프로젝트의 테스트 명령을 설정 파일에서 찾는다:
`package.json` scripts / `pyproject.toml` / `Makefile` / `build.gradle` /
`Cargo.toml` / CI 설정 파일.

**명령을 지어내지 않는다.** 찾지 못하면 리더에게 문의한다.

### 2. 실행 순서

느린 것을 뒤로 미뤄 빠른 피드백을 먼저 준다.

| 순서 | 대상 | 실패 시 |
|------|------|--------|
| 1 | **아키텍처 검증** | **즉시 중단하고 보고.** 구조가 깨진 상태에서 나머지는 무의미 |
| 2 | 단위 | 계속 진행 (전체 결과 수집) |
| 3 | 통합 | 계속 진행 |
| 4 | E2E (headless) | 계속 진행 |
| 5 | 커버리지 집계 | - |

아키텍처 검증만 즉시 중단하는 이유: 계층 위반은 개별 테스트 실패가 아니라
**구조적 결함**이므로, 다른 테스트 결과를 수집해도 어차피 재작업한다.

### 3. E2E는 headless로만

`harness/principles/testing.md` 3절. **창을 띄우는 명령을 실행하지 않는다.**
CI에 디스플레이가 없고, 로컬에서는 사용자 작업을 방해하며, 결과가 화면에만
남아 자동 판정이 불가능하다.

브라우저·시뮬레이터 실행이 불가능하면 **미실행으로 기록**한다.

### 4. 커버리지 측정

**라인과 브랜치를 모두 측정한다.** 라인만 높고 브랜치가 낮으면 분기 조건이
검증되지 않은 것이다.

계층별 기준 (`harness/principles/testing.md` 5절):

| 계층 | 라인 하한 |
|------|----------|
| Domain | 90% |
| Application | 80% |
| Adapter | 60% |
| Infrastructure | 없음 (통합 테스트로 대체) |
| 전체 | 75% |

**커버리지 숫자를 맞추려 무의미한 테스트를 작성하지 않는다.**
미달 영역이 어디인지 알리는 것이 숫자를 채우는 것보다 유용하다.

### 5. 리포트 작성

`docs/test/test-report.md` — **매번 덮어쓴다.** 최신 상태만 의미가 있고,
이력은 CI 아티팩트에 남는다.

템플릿: `docs/template/test-report.md`

필수 섹션:

| 섹션 | 내용 |
|------|------|
| 요약 | 판정(PASS/FAIL), 총계, 커버리지, 실행 시각, **미실행 영역** |
| 계층별 결과 | 실행/성공/실패/스킵/소요 |
| 실패 상세 | 테스트명, 위치, 오류 메시지, **추정 원인**, 담당 |
| 커버리지 상세 | 계층별 라인·브랜치 + 기준 대비 판정 |
| 커버리지 미달 영역 | 파일별 미커버 내용 |
| 스킵된 테스트 | 사유와 조치 필요 여부 |
| **미실행 영역** | 사유와 그로 인한 위험 |

### 6. 판정

| 상황 | 판정 |
|------|------|
| 아키텍처 검증 실패 | **FAIL** |
| 테스트 실패 1건 이상 | **FAIL** |
| 전체 테스트 0건 | **FAIL** (테스트 부재) |
| 커버리지 기준 미달 | FAIL. 단 사유가 기록되면 게이트에서 판단 |
| 핵심 영역 미실행 | **FAIL로 판정하지 않되, 미실행을 명시**하여 게이트가 판단하게 한다 |
| 전부 통과 + 기준 충족 | PASS |

**"전체 테스트 0건"이 PASS가 아니라는 점이 중요하다.** 실행할 테스트가
없는 것은 성공이 아니라 미완성이다.

## 하지 않는 것

| 금지 | 이유 |
|------|------|
| 테스트를 고쳐서 통과시키기 | 결함 은폐. 실패는 구현 에이전트에게 반환한다 |
| 실패 테스트를 skip 처리 | 같음 |
| 커버리지 목표에 맞춘 무의미 테스트 작성 | 지표만 오르고 품질은 그대로 |
| 실패를 "일부 실패"로 뭉개기 | 건수·이름·오류를 그대로 싣는다 |
| 미실행을 통과로 보고 | 가장 심각한 위반 |

**예외:** 테스트 자체의 명백한 결함(오타, 잘못된 경로, 존재하지 않는 픽스처)은
직접 고치되, **그 사실을 리포트에 기록**한다.

## 실패 반환

실패는 담당 구현 에이전트에게 다음 형식으로 반환한다:

```
테스트 실패: test_만료된_세션은_조회되지_않는다
위치: tests/domain/test_session.py:88
오류: AssertionError: expected None, got Session(id='s-1')
추정 원인: 만료 판정이 `>` 대신 `>=` 여야 함 (src/domain/session.py:34)
```

추정 원인을 붙이면 수정이 빨라진다. 확신이 없으면 "추정"임을 명시한다.

## 에러 핸들링

| 상황 | 대응 |
|------|------|
| 의존성 미설치 | 설치 시도 → 실패 시 미실행으로 기록 |
| 테스트 무한 대기 | 타임아웃 후 중단, 해당 테스트를 보고 |
| DB·컨테이너 기동 실패 | 통합 테스트를 미실행으로 기록. 단위 테스트는 진행 |
| 브라우저 미설치 | E2E 미실행으로 기록 |
| 커버리지 도구 없음 | 테스트만 실행하고 커버리지 미측정 명시 |
