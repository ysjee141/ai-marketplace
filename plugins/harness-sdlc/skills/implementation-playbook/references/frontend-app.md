## 1. 구조 분리

앱 테스트는 시뮬레이터 기동 때문에 느리다. **순수 로직을 분리하는 이득이
웹보다 훨씬 크다.**

```
lib/ (또는 src/)
├── domain/          순수 로직 — 검증, 계산, 상태 전이. 플랫폼 무관
├── data/            API 클라이언트, 로컬 저장소, 리포지토리
├── presentation/    화면, 위젯/컴포넌트, 뷰모델
└── platform/        플랫폼 분기 어댑터 (여기에만 분기가 존재)
```

`domain/`은 시뮬레이터 없이 밀리초 단위로 테스트된다. 로직의 대부분을
여기에 두는 것이 목표다.

## 2. 앱 생명주기

**설계서에 없더라도 반드시 확인하고 구현한다.** 웹에는 없는 관심사이며,
누락되면 "가끔 로그인이 풀린다" 같은 재현 어려운 버그가 된다.

| 상황 | 확인할 것 |
|------|----------|
| 백그라운드 전환 | 진행 중 작업 처리, 타이머 중단 |
| 포그라운드 복귀 | 토큰 만료 확인, 데이터 재검증 |
| 프로세스 강제 종료 | 작성 중 데이터 보존 여부 |
| 저메모리 상태 복원 | 화면 스택과 입력값 복원 |
| 딥링크 진입 | 인증 상태별 분기, 백스택 구성 |
| 회전·분할 화면 | 레이아웃과 상태 유지 |

**복귀 시 토큰 만료 확인**을 빠뜨리면 첫 요청이 401로 실패한다.

## 3. 네트워크와 오프라인

모바일에서 네트워크 불안정은 예외가 아니라 **기본 전제**다.

| 항목 | 요구 |
|------|------|
| 타임아웃 | 연결·읽기 각각 설정. 무한 대기 금지 |
| 재시도 | **멱등 요청만.** 지수 백오프 + 지터 |
| 오프라인 표시 | 사용자에게 상태를 알린다 |
| 큐잉 | 오프라인 중 작업을 큐에 넣고 복구 시 전송 (필요한 경우) |
| 페이로드 | 왕복 횟수가 곧 체감 성능. 조합 API를 요청할 수 있다 |

재시도 정책은 `network-engineer`와 합의한다. 클라이언트가 임의로 재시도하면
서버 측 중복 처리가 발생한다.

## 4. 권한

**권한 거부 경로를 구현하지 않은 화면은 미완성이다.**

| 단계 | 구현 |
|------|------|
| 요청 전 | 왜 필요한지 설명하는 사전 안내 |
| 거부됨 | 기능 제한 상태의 화면. 크래시 금지 |
| 영구 거부 | 설정 앱으로 유도 |
| 런타임 취소 | 앱 복귀 시 권한 재확인 |

권한이 필요한 기능은 **권한 없이도 앱이 동작**해야 한다.

## 5. 로컬 저장소

| 데이터 | 저장소 |
|--------|--------|
| 토큰·비밀 | **보안 저장소(Keychain/Keystore)**. 일반 저장소 금지 |
| 설정 | 키-값 저장소 |
| 캐시 | 파일 또는 로컬 DB. 만료 정책 필수 |
| 오프라인 데이터 | 로컬 DB. 동기화 전략 명시 |

**토큰을 일반 저장소에 넣는 것은 보안 결함**으로 취급한다.
저장 위치를 impl-notes에 기록한다.

## 6. 플랫폼 분기

분기를 화면 코드에 흩뿌리면 유지 불가능해진다. **`platform/` 어댑터 한 곳에 모은다.**

```dart
// platform/haptics.dart — 분기가 여기에만 존재
abstract class Haptics { void tap(); }
class IosHaptics implements Haptics { ... }
class AndroidHaptics implements Haptics { ... }
```

화면 코드는 `Haptics` 인터페이스만 안다. 플랫폼이 추가되어도 화면은 그대로다.

**플랫폼 간 동작 차이를 발견하면 한쪽만 맞추지 않는다.** 차이를 보고하고
`architect`와 처리 방침을 정한다.

## 7. 테스트

| 대상 | 방식 | 요구 |
|------|------|------|
| `domain/` | 단위 | 시뮬레이터 없이. 대부분의 테스트가 여기 |
| 위젯/컴포넌트 | 위젯 테스트 | 렌더링 + 상호작용 |
| 데이터 계층 | 통합 | 목 서버로 성공·실패·오프라인 |
| 생명주기 | 통합 | 백그라운드↔포그라운드 전환 시나리오 |
| 사용자 여정 | E2E | headless |

**생명주기 테스트를 빠뜨리지 않는다.** 수동 확인만으로는 회귀를 잡을 수 없다.

## 8. E2E silent 설정

`harness/principles/testing.md` 3절 필수 준수.

| 도구 | 설정 요지 |
|------|----------|
| Detox (RN) | `--headless`, 시뮬레이터 사전 부팅, `--record-logs failing` |
| Maestro | `maestro test --format junit`, 헤드리스 에뮬레이터 |
| Patrol / integration_test (Flutter) | 헤드리스 디바이스, `--machine` 출력 |
| XCUITest / Espresso | CI 러너에서 헤드리스 시뮬레이터·에뮬레이터 |

### 공통 규칙

- 시뮬레이터·에뮬레이터를 **사전 부팅**하고 테스트마다 상태를 초기화한다
- 기계 판독 리포터 필수. 실패 시에만 스크린샷·비디오
- 고정 `sleep` 금지 — 조건 기반 대기
- **실제 기기·스토어 계정·결제가 필요한 시나리오는 E2E 대상에서 제외**하고
  수동 확인 항목으로 명시한다. 무리하게 자동화하면 불안정해진다

**시뮬레이터 실행이 불가능한 환경이면** E2E를 작성하되 실행은 건너뛰고
**미실행을 명시**한다.

## 스토어 배포 고려

구현 중 다음을 발견하면 **즉시 보고한다.** 배포 시점에 발견하면 비용이 크다.

- 스토어 정책 위반 소지 (권한 과다 요청, 외부 결제 유도, 사용자 데이터 처리)
- 최소 지원 OS 버전과 사용 API의 불일치
- 앱 크기 제한 초과 가능성
- 코드 서명·프로비저닝 요구
