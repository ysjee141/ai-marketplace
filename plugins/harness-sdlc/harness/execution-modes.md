# 실행 모드

[실행 규약](runtime.md)의 유효 설정과 실제 호스트 기능을 기준으로 수행한다.
모드는 누가 작업하는지를 바꾸며 선택한 작업 경로의 검증 기준을 바꾸지 않는다.

## 1. 모드

| 모드 | 생성·구현 | 검토·QA |
|---|---|---|
| skill | 메인 순차 역할 수행 | 별도 검토 단계에서 파일·체크리스트 대조 |
| balanced | 메인 | 가능한 경우 독립 에이전트 |
| agent | 독립 작업 병렬 위임, 의존 작업 순차 위임 | 별도 리뷰어와 모듈별 QA |

기획 인터뷰와 사용자 선택 조율은 메인이 담당한다.
위임 권한·기능이 없으면 skill 방식으로 수행하고 requested_mode와 execution_mode를 구분해 기록한다.
도구·모델·동시 실행 수는 현재 호스트의 지침을 따른다.

## 2. 역할 전달

위임할 때 프로젝트 루트, slug, 역할 파일, 스킬 파일, 입력·출력 경로,
유효 설정 스냅샷, 추가 규칙과 파일 소유 범위를 전달한다.
결과는 파일로 보존하고, 산출물이 없거나 검증이 실패하면 작업 완료로 처리하지 않는다.
역할 매핑은 `harness/pipeline.md`를 따른다.

## 3. 선택과 전환

기본값은 `harness/defaults.json`, 프로젝트 변경값은 `.harness/project.json`의 settings다.
작업 설정과 사용자 명시 지시는 이 값보다 우선한다.
ask인 경우 아직 결정되지 않은 모드만 질문한다. “제대로” 같은 표현만으로 agent 모드나
더 비싼 모델을 선택하지 않는다.

WBS 완료 후 auto_suggest_mode가 true일 때:
- 상향: suggest_thresholds.upgrade_to_agent의 tasks / roles / parallel_rounds 중 하나 이상 충족.
- 하향: suggest_thresholds.downgrade_to_skill의 tasks / roles 상한을 모두 충족.

변경은 제안하며, 사용자가 이미 해당 선택을 위임·지정한 경우 그 범위를 따른다.
진행 중에는 산출물을 저장하고 단계 경계에서 전환한다. 현재 위임 작업을 정리하고
state.json·walkthrough·effective-config.json에 변경 이유를 기록한다.

## 4. 비용 관리

각 단계에서 필요한 스킬·영역별 reference만 읽는다.
단계 종료 시 산출물을 저장하고 다음 단계는 필요한 파일을 읽어 시작한다.
독립 작업이 없으면 병렬화를 위한 팀을 만들지 않는다.

## 5. 품질 보정

- skill 리뷰는 생성 완료 후 별도의 검토 단계에서 수행한다. 새 사용자 턴은 필요 없다.
- 파일과 체크리스트의 항목별 근거를 먼저 쓰고 판정을 선언한다.
- 같은 세션에서 생성 맥락을 제거할 수 없으므로 독립 검증과 같다고 주장하지 않는다.
- 순차 분석 후 결과를 대조한 교차 검토를 기록한다.
- QA는 계약 → 생산자 → 소비자 순으로 대조한다.
- 경계면 변경은 공유 파일에 기록하고 영향받는 Task 시작 전에 읽는다.

## 6. 불변 사항

미실행을 통과로 보고하지 않는다. 실패·미결정·중단 사유와 재개 지점을 파일에 남긴다.
유효 설정의 품질 기준과 반려 한계를 동일하게 적용하고, 결함 발생 단계로 롤백한다.
모드 변경만으로 외부 작업의 허가나 사용자 요청 범위가 확대되지 않는다.
