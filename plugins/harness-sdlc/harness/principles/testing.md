# 테스트 원칙

> **모든 코드는 테스트 코드가 존재해야 한다.** 이것은 협상 대상이 아니다.
> 테스트가 없는 코드는 미완성 코드로 간주하고 리뷰 게이트에서 반려한다.

## 1. 테스트 계층 구조

| 계층 | 대상 | 격리 수준 | 목표 비중 | 실행 속도 |
|------|------|----------|----------|----------|
| **Unit** | 순수 함수, 값 객체, 엔티티, 유스케이스(포트 스텁) | 완전 격리, I/O 없음 | 70% | ms 단위 |
| **Integration** | 리포지토리 구현, 외부 API 클라이언트, 매퍼 | 실제 DB/컨테이너 사용 | 20% | 초 단위 |
| **E2E** | 사용자 시나리오 전체 경로 | 실제 구동 환경 | 10% | 분 단위 |
| **Architecture** | 의존성 규칙, 계층 경계, 명명 규칙 | 정적 분석 | 별도 | ms 단위 |

**비중은 목표이지 강제가 아니다.** 다만 E2E가 30%를 넘으면 피드백 루프가 무너진
신호이므로 유스케이스 단위 테스트로 내려야 한다.

## 2. 작성 기준

### 테스트 이름

동작을 문장으로 서술한다. 구현이 아니라 **의도**를 적는다.

```
# 나쁨
test_calculate_1()
test_discount_function()

# 좋음
test_10만원_초과_주문은_10퍼센트_할인이_적용된다()
test_취소된_주문은_다시_취소할_수_없다()
```

### 구조 — Given / When / Then

세 구간을 빈 줄로 구분한다. 주석은 필요할 때만.

```
def test_취소된_주문은_다시_취소할_수_없다():
    order = Order.placed(id="o-1").cancel(reason="변심")

    with pytest.raises(AlreadyCancelled):
        order.cancel(reason="중복")
```

### 무엇을 테스트하는가

| 반드시 테스트 | 테스트하지 않음 |
|--------------|---------------|
| 비즈니스 규칙, 불변식 | 언어/프레임워크 자체 기능 |
| 경계값 (0, 1, 최대, 음수, 빈 컬렉션) | 단순 getter/setter |
| 상태 전이 (허용/금지 모두) | 자동 생성 코드 |
| 에러 경로와 예외 메시지 | 외부 라이브러리 내부 동작 |
| 경계면 계약 (API shape, DB 매핑) | 로그 출력 문구 |

### 테스트 대역(Test Double)

- **Application 계층 테스트**: 포트 인터페이스를 **인메모리 Fake**로 구현한다.
  Mock 프레임워크의 호출 검증(`verify`)은 최소화한다 — 구현에 결합되어
  리팩터링을 방해하기 때문이다.
- **시각·난수·ID**: 절대 직접 호출하지 않는다. 포트로 주입하고 테스트에서 고정값을 넣는다.
  이것이 순수성 원칙이 테스트에 주는 실질적 이득이다.

### 테스트 우선 여부

TDD를 강제하지 않는다. 단, **구현 Task의 완료 조건에 테스트가 포함**되며,
테스트를 나중에 작성하더라도 같은 PR 안에 있어야 한다.
"테스트는 다음 PR에서"는 허용하지 않는다.

## 3. E2E 테스트 — silent 모드 필수

프론트엔드가 존재하면 E2E 테스트를 작성한다. **반드시 headless / silent로 실행**한다.

### 이유

에이전트 기반 파이프라인에서 브라우저 창이 뜨면:
- CI 환경(디스플레이 없음)에서 실패한다
- 로컬 실행 시 사용자 작업을 방해한다
- 실행 로그가 아니라 화면으로만 결과가 남아 자동 판정이 불가능하다

### 요구 사항

| 항목 | 규칙 |
|------|------|
| 실행 모드 | headless 기본값. 헤드풀은 명시적 로컬 디버그 플래그로만 |
| 리포터 | 기계 판독 가능한 형식(JSON/JUnit XML) **필수**. 콘솔 리포터는 부가 |
| 아티팩트 | 실패 시에만 스크린샷/트레이스/비디오 저장 |
| 대기 방식 | 고정 `sleep` 금지. 조건 기반 대기만 사용 |
| 데이터 | 테스트마다 격리된 시드 데이터. 테스트 간 순서 의존 금지 |
| 종료 코드 | 실패 시 non-zero 종료. 파이프라인이 판정할 수 있어야 함 |

### 도구별 silent 설정 요지

| 도구 | 핵심 설정 |
|------|----------|
| Playwright | `use: { headless: true }`, `reporter: [['json', {outputFile}], ['line']]` |
| Cypress | `cypress run` (open 금지), `--reporter json`, `video: false` (실패 시만) |
| Selenium | `--headless=new` 인자, WebDriver 로그 레벨 축소 |
| Detox (RN) | `--headless` + 시뮬레이터 사전 부팅 |

구체 설정 예시는 `implementation-playbook`의 각 플랫폼 reference에 둔다.

## 4. 아키텍처 검증 테스트

`architecture.md` 7절의 규칙을 **실행 가능한 테스트**로 구현한다.
문서로만 존재하는 원칙은 반드시 침식된다.

### 구현 형태

일반 테스트 스위트 안의 별도 파일/디렉토리로 둔다 (`tests/architecture/`).
CI에서 다른 테스트와 함께 실행되며, 위반 시 빌드를 실패시킨다.

### 최소 세트 (A1~A4)

```
# 예: 파이썬 — Domain 계층 의존성 검증
def test_domain_계층은_외부_계층을_import하지_않는다():
    violations = []
    for path in glob("src/domain/**/*.py"):
        for imported in extract_imports(path):
            if imported.startswith(("src.application", "src.adapter", "src.infra")):
                violations.append(f"{path} → {imported}")
    assert not violations, "의존성 규칙 위반:\n" + "\n".join(violations)
```

### 도구 옵션

| 언어 | 도구 |
|------|------|
| Java/Kotlin | ArchUnit |
| TypeScript/JS | dependency-cruiser, eslint-plugin-boundaries |
| Python | import-linter, pytest-archon |
| Go | go-arch-lint, depguard |
| C# | NetArchTest |

전용 도구가 없으면 **직접 import 그래프를 파싱하는 테스트를 작성한다.**
30줄 내외면 충분하며, 외부 의존성을 줄이는 이점도 있다.

### 검증 테스트 확장 시점

- 새 계층/모듈이 추가될 때 → 경계 규칙 추가
- ADR로 원칙 예외가 승인될 때 → 해당 예외를 **명시적 allowlist**로 테스트에 기록
  (예외가 코드에 남으므로 나중에 원복 여부를 추적할 수 있다)

## 5. 커버리지 기준

커버리지는 **목표가 아니라 진단 지표**다. 숫자를 맞추려 무의미한 테스트를
작성하는 것을 금지한다.

| 대상 | 라인 커버리지 하한 | 근거 |
|------|------------------|------|
| Domain 계층 | **90%** | 순수 로직이므로 테스트 비용이 낮다. 낮으면 규칙이 검증 안 된 것 |
| Application 계층 | **80%** | 유스케이스 주요 경로 + 에러 경로 |
| Interface Adapter | **60%** | 매퍼·컨트롤러 계약 중심 |
| Infrastructure | 하한 없음 | 통합 테스트로 대체 |
| 전체 | **75%** | 게이트 기준 |

**브랜치 커버리지도 함께 측정한다.** 라인만 높고 브랜치가 낮으면
분기 조건이 검증되지 않은 것이다.

측정 결과는 `test-execution` 스킬이 `docs/test/test-report.md`에 기록하며,
**매번 overwrite**한다 (최신 상태만 유지).

### 커버리지 하락 규칙

PR에서 전체 커버리지가 직전 대비 **1%p 이상 하락하면 리뷰 게이트에서 반려**한다.
불가피하면 사유를 PR 본문과 테스트 리포트에 기록한다.

## 6. 테스트 금지 사항

| 금지 | 이유 |
|------|------|
| `sleep` 기반 대기 | 느리고 불안정(flaky). 조건 대기로 대체 |
| 실행 순서에 의존하는 테스트 | 병렬 실행·부분 실행 시 깨진다 |
| 프로덕션 DB/외부 API 호출 | 결정성 없음, 부작용 위험 |
| 하드코딩된 현재 날짜 비교 | 시간이 지나면 깨진다. 시각을 주입하라 |
| 여러 동작을 한 테스트에 몰아넣기 | 실패 원인 파악 불가 |
| 테스트를 통과시키려 프로덕션 코드에 테스트 전용 분기 추가 | 설계 결함의 은폐 |
| skip/xfail 방치 | 매 실행마다 리포트에 남기고, 게이트에서 사유를 확인 |
