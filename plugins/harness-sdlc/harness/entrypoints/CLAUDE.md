# CLAUDE.md

이 저장소는 **SDLC 개발 파이프라인 하네스**를 사용한다.
개발 작업은 기획 → 분석 → 계획 → 설계 → 구현 → 테스트 → 리뷰 → 배포 순으로
진행하며, 각 단계는 리뷰 게이트로 통제된다.

## 하네스: SDLC 개발 파이프라인

**목표:** 아키텍처 원칙과 리뷰 게이트로 전 주기를 통제하며,
코딩 에이전트 종류와 무관하게 동작한다.

**트리거:** 개발 작업 요청(기능 개발·버그 수정·리팩터링·CI 구축) 시
`sdlc-orchestrator` 스킬을 사용하라. 단계별 단독 요청(PRD 작성, 설계, 테스트 실행,
리뷰 등)은 해당 단계 스킬을 직접 사용해도 된다. 단순 질문은 직접 응답 가능.

**작업 시작 전:** `_workspace/walkthrough.md`가 있는지 먼저 확인하라.
있으면 진행 중인 작업이 있으므로 덮어쓰지 말고 재개 여부를 사용자에게 묻는다.

**실행 모드:** 파이프라인은 세 모드로 돌릴 수 있다. 기본값은
`harness/config.yml`의 `execution_mode`이며, 사용자 지시가 우선한다.

| 모드 | 위임 | 서브에이전트 | 언제 |
|------|------|-------------|------|
| `skill` | 없음 | 0 | 토큰 절약, 소규모 변경 |
| `balanced` | 게이트 리뷰 + QA | 3~7 | **기본** — 일반 기능 개발 |
| `agent` | 분석·구현은 팀 | 12~25 | Task 15개 이상, 영역 3개 이상 |

모드는 **누가 수행하는가**만 바꾼다. 산출물·게이트 기준은 동일하다.
상세: `harness/execution-modes.md`

## 구조

| 경로 | 역할 |
|------|------|
| `harness/config.yml` | 실행 모드·품질 기준 설정 |
| `harness/` | 도구 중립 SOT — 원칙, 파이프라인·실행모드 정의, 어댑터, 스크립트 |
| `.claude/agents/` | 에이전트 정의 |
| `.claude/skills/` | 스킬 (오케스트레이터 포함) |
| `docs/template/` | 문서 템플릿 |
| `docs/` | 승격된 산출물 (`prd`, `plan`, `design`, `test`, `review`, `report`) |
| `_workspace/` | 진행 중 작업 산출물 — **커밋하지 않는다** |
| `AGENTS.md` | 범용 코딩 에이전트 진입점 — 요청→스킬 라우팅 표 포함 |

## 불변 규칙

파이프라인 실행 시 다음은 협상 대상이 아니다:

1. **모든 코드에 테스트가 존재한다.** 같은 PR 안에.
2. **E2E는 silent(headless)로만 실행한다.** 창을 띄우는 명령을 실행하지 않는다.
3. **실행하지 않은 것을 실행했다고 보고하지 않는다.** 미실행은 미실행으로 명시한다.
4. **`_workspace/`는 커밋되지 않는다.** 지속 참조가 필요하면 사용자 승인 후 승격한다.
5. **`walkthrough.md`를 단계·게이트마다 갱신한다.** 세션 단절 시 복구의 유일한 근거다.
6. **ADR 승인 없이 설계로 넘어가지 않는다.**
7. **게이트 3회 반려 시 자동 재작업을 중단하고 사용자에게 보고한다.**
8. **게이트는 실행 모드와 무관하게 반드시 실행한다.** 토큰이 부족하면 모드를
   낮추거나 범위를 줄이되, 기준은 유지한다.
