# 범용 에이전트 어댑터

먼저 [실행 규약](../runtime.md)을 읽는다.
Codex 등 각 호스트가 제공한 실제 스킬 위치로 플러그인 루트를 찾는다.
Claude 전용 환경 변수·팀 API·모델명을 사용 가능하다고 가정하지 않는다.

## 시작

마켓플레이스에서 플러그인을 설치하고 `harness-init`으로 프로젝트를 설정한다.
스킬 자동 탐색을 지원하는 호스트에서는 설치된 스킬을 직접 사용한다.
자동 탐색이 없는 환경은 사용자가 제공한 패키지 경로와
`harness/entrypoints/AGENTS.md`의 라우팅 표를 사용한다.

## 역할과 위임

실제 도구와 사용자 지시에서 위임 가능 여부를 확인한다.
가능하면 선택한 실행 모드대로 `agents/{role}.md`를 읽어 역할 지침을 전달한다.
불가능하면 skill 방식으로 순차 수행하고 state.json에 요청 모드와 실제 모드를 기록한다.

역할 전환 시:
1. 이전 산출물을 프로젝트 파일로 저장한다.
2. 새 역할과 필요한 스킬·reference를 읽는다.
3. 산출물 파일에서 입력을 읽고 작업한다.

순차 분석은 두 분석 결과를 함께 읽어 교차 검토하고
`_workspace/{slug}/02_analysis/_cross-review.md`에 상충 주장과 공백을 기록한다.
경계면 변경은 `_workspace/{slug}/05_implement/_messages.md`에 기록한다.

## 검토

위임할 수 없는 검토는 별도의 검토 단계로 수행한다. 사용자의 새 턴을 요구하지 않는다.
계약 → 생산자 → 소비자 순서로 읽고 체크리스트 항목별 근거를 적은 뒤 판정한다.
같은 세션에서는 생성 맥락을 지울 수 없으므로 독립 검증과 동등하다고 주장하지 않는다.

## 기능 부재

| 없는 기능 | 대응 |
|---|---|
| 팀·메시지 | 순차 수행, 프로젝트 파일로 전달 |
| 검색 | 기존 자료로 가능한 범위를 조사하고 미확인 근거를 표시 |
| 쓰기 | 생성할 내용을 제시하고 미저장을 명시 |
| 실행 도구 | 미실행을 명시하고 사용자가 실행할 명령을 제시 |
| Python | 프로필 형식대로 직접 작성·병합, 기계 검증 미실행 표시 |

설치된 플러그인을 프로젝트로 재복사하지 않는다.
