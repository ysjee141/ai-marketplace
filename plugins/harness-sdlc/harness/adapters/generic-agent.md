# 범용 코딩 에이전트 어댑터

멀티 에이전트 기능(팀·서브 에이전트·공유 작업 목록)이 없거나 제한적인 코딩
에이전트에서 이 하네스를 운영하는 방법. **Codex CLI, Cursor, GitHub Copilot,
Gemini CLI, Aider, Cline 등 대부분의 도구가 이 어댑터를 사용한다.**

## 핵심 전제

이 하네스의 본체는 `harness/`와 `docs/template/`의 **일반 마크다운**이다.
멀티 에이전트는 **속도를 위한 최적화이지 정확성의 조건이 아니다.**
단일 에이전트가 역할을 순차적으로 전환해도 동일한 산출물에 도달해야 한다.

> 이 어댑터의 방식은 `harness/execution-modes.md`의 **`skill` 모드와 동일하다.**
> 도구가 서브에이전트를 지원하더라도 토큰을 아끼려면 같은 방식을 쓸 수 있다.
> 모드별 품질 보정 절차는 `execution-modes.md` 5절을 함께 참조한다.

## 1. 역할 전환 방식

에이전트를 스폰하는 대신, **한 세션에서 역할을 명시적으로 선언하고 전환**한다.

```
현재 역할: codebase-analyst
참조: .claude/agents/codebase-analyst.md, .claude/skills/codebase-analysis/SKILL.md
입력: _workspace/user-auth/01_planning/prd-draft.md
출력: _workspace/user-auth/02_analysis/02_codebase-analyst_risk.md
```

역할 전환 시 반드시:
1. 이전 역할의 산출물을 **파일로 저장**한다 (컨텍스트에만 두지 않는다)
2. 새 역할의 정의 파일과 스킬을 **다시 읽는다**
3. 새 역할은 이전 역할의 산출물을 **파일에서 읽어** 시작한다

> 파일 경유가 핵심이다. 컨텍스트를 통해 넘기면 역할 간 경계가 흐려지고,
> 리뷰 역할이 자기 작업을 검토하는 자기 승인 편향이 발생한다.

## 2. 병렬 단계의 순차 대체

| 원래 설계 | 범용 어댑터에서 |
|----------|---------------|
| 02 분석: research-analyst ∥ codebase-analyst | 순차 실행. 단, **두 산출물을 각각 완성한 뒤** 교차 검토 라운드를 1회 추가 |
| 05 구현: 영역별 에이전트 팀 | Task 목록 순서대로 순차 실행. 경계면을 공유하는 Task는 **연속 배치** |
| 팀원 간 SendMessage | 공유 파일에 기록: `_workspace/{slug}/NN_stage/_messages.md` |

### 교차 검토 라운드

병렬 협업의 이점(발견 공유·상호 도전)을 복원하기 위한 보완 절차.
병렬로 설계된 단계를 순차 실행한 뒤, 다음을 수행한다:

1. 모든 산출물을 함께 읽는다
2. 다음을 명시적으로 점검한다:
   - 상충하는 주장이 있는가? → 출처를 병기하고 판단 근거를 기록
   - A의 발견이 B의 결론을 바꾸는가? → 해당 산출물을 갱신
   - 양쪽 모두 다루지 않은 공백이 있는가? → 추가 조사
3. 결과를 `_workspace/{slug}/NN_stage/_cross-review.md`에 기록한다

## 3. 리뷰 게이트의 독립성 확보

단일 에이전트가 생성과 리뷰를 모두 수행하면 판정이 관대해진다.
다음 규칙으로 독립성을 근사한다:

1. **리뷰는 반드시 별도 턴에서** 수행한다. 생성 직후 같은 응답에서 판정하지 않는다
2. 리뷰 시작 시 **산출물 파일만 읽고**, 생성 과정의 추론을 참조하지 않는다
3. 리뷰 스킬(`review-gate`)의 체크리스트를 **항목별로 명시적으로 판정**한다.
   "전반적으로 양호"는 판정이 아니다
4. 게이트 판정 파일을 먼저 작성하고, 그 다음에 통과/반려를 선언한다
5. 도구가 서브 에이전트를 지원하면 리뷰만이라도 별도 에이전트로 분리한다

## 4. 상태 관리

멀티 에이전트 도구의 공유 작업 목록을 파일로 대체한다.

| 기능 | 파일 대체 |
|------|----------|
| 공유 작업 목록 | `_workspace/{slug}/03_plan/tasks.md` (체크박스 + 상태 열) |
| 진행 상황 | `_workspace/walkthrough.md` |
| 기계 판독 상태 | `_workspace/{slug}/state.json` |
| 에이전트 간 메시지 | `_workspace/{slug}/NN_stage/_messages.md` |

`tasks.md` 형식:

```markdown
| ID | Task | 담당 역할 | 선행 | 상태 | 산출물 |
|----|------|----------|------|------|--------|
| T1 | 사용자 엔티티 및 값 객체 구현 | backend-engineer | - | done | src/domain/user/ |
| T2 | 인증 유스케이스 구현 | backend-engineer | T1 | in_progress | - |
| T3 | 로그인 화면 구현 | frontend-web-engineer | T2 | pending | - |
```

## 5. 도구별 진입점

각 도구가 자동으로 읽는 파일에서 하네스를 가리킨다.

`install.sh`가 다음을 자동 배치한다. **이미 존재하면 덮어쓰지 않고 병합 필요로 보고**한다.

| 도구 | 진입 파일 | 내용 |
|------|----------|------|
| Codex CLI, Cursor(최신), Jules 등 | `AGENTS.md` | **정본** — 라우팅 표 + 역할 매핑 + 불변 규칙 |
| Claude Code | `CLAUDE.md` | 트리거 규칙 + 변경 이력 |
| Gemini CLI | `GEMINI.md` | `AGENTS.md`를 가리키는 포인터 |
| Cursor (규칙 방식) | `.cursor/rules/harness.mdc` | 포인터 + `alwaysApply: true` frontmatter |
| GitHub Copilot | `.github/copilot-instructions.md` | 포인터 |
| Aider | `CONVENTIONS.md` | 포인터 |

### 왜 포인터인가 — 내용을 복제하지 않는다

2차 진입 파일에 `AGENTS.md` 내용을 복사하면 **두 벌이 되어 반드시 어긋난다.**
하네스를 고칠 때마다 6개 파일을 동기화하는 것은 유지되지 않는다.
포인터는 "`AGENTS.md`를 읽어라" 한 문장이면 충분하며, 도구는 그 지시를 따라 Read한다.

### AGENTS.md의 구성

| 섹션 | 역할 | 왜 여기 있어야 하는가 |
|------|------|---------------------|
| 먼저 읽을 것 | 상황별 참조 파일 | 진입 직후 어디로 갈지 |
| **요청 → 스킬 라우팅** | 사용자 발화 → 스킬 매핑 | **범용 도구에는 자동 트리거가 없다.** 이 표가 Claude Code의 `description` 트리거를 대신한다 |
| 단계 → 역할 → 절차 매핑 | 파이프라인 단계 → 파일 경로 | 오케스트레이션 진행 시 |
| 역할 전환 규칙 | 파일 경유 전환 절차 | `skill` 모드의 실행 방법 |
| 리뷰 게이트 독립성 | 판정 편향 보정 | 단일 에이전트의 최대 약점 |
| 불변 규칙 | 협상 불가 항목 | 모드·도구와 무관 |

`AGENTS.md`는 **얇게 유지한다.** 파이프라인 상세는 `harness/pipeline.md`에,
역할은 `.claude/agents/`에, 절차는 `.claude/skills/`에 있다. 이 파일들은
frontmatter가 붙은 **일반 마크다운**이므로 도구와 무관하게 읽을 수 있다 —
디렉토리 이름만 Claude Code 관례를 따를 뿐이고, Claude Code가 그것을 **추가로
자동 스캔**할 뿐이다. 다른 도구는 경로를 알려주면 Read로 읽는다.

## 6. 기능 부재 시 대체표

| 하네스가 기대하는 것 | 없을 때 대체 |
|-------------------|-------------|
| 서브 에이전트 스폰 | 역할 선언 후 순차 전환 (1절) |
| 에이전트 팀 / 메시지 | `_messages.md` 파일 기반 통신 (4절) |
| 스킬 자동 트리거 | 사용자가 스킬 파일 경로를 명시하거나, `AGENTS.md`에 단계별 참조 표를 둔다 |
| 백그라운드 실행 | 순차 실행. 대기 시간이 긴 작업(테스트)은 사용자에게 실행 요청 |
| 웹 검색 | 사용자에게 자료 제공 요청. **추측으로 대체하지 않는다** |
| 파일 쓰기 권한 | 사용자에게 파일 내용을 제시하고 저장 요청 |

**공통 원칙:** 기능이 없어서 수행하지 못한 검증은 **누락으로 명시**한다.
수행한 것처럼 보고하지 않는다.
