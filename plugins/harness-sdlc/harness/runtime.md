# 실행 컨텍스트 — 모든 스킬과 역할의 공통 규약

## 경로 경계

이 하네스는 마켓플레이스 플러그인이다. 프로젝트로 복사 설치하지 않는다.

- **플러그인 루트**: 지금 읽은 `skills/{name}/SKILL.md`에서 두 단계 위.
  역할 파일 `agents/{name}.md`에서는 한 단계 위다. 호스트가 알려 준 실제
  스킬 위치를 사용한다. Claude의 `${CLAUDE_PLUGIN_ROOT}`도 사용할 수 있지만
  다른 호스트에서 같은 변수가 있다고 가정하지 않는다.
- 본문의 `harness/`, `skills/`, `agents/`, `docs/template/`는 **플러그인 루트 기준 자산**이다.
  `references/`는 해당 스킬 디렉터리 기준이다. `../../` 참조는 패키지 밖으로 나가지 않는다.
- **프로젝트 루트**: 사용자가 작업 대상으로 지정한 저장소. 모노레포에서는 적용할
  하위 프로젝트를 확인한다. 플러그인 위치나 현재 셸 디렉터리를 대상이라고 추정하지 않는다.
- `.harness/`, `_workspace/`, `docs/`(template 제외), 소스 코드 경로는 **프로젝트 루트 기준**이다.
- 플러그인 캐시에는 쓰지 않는다. 업데이트로 경로가 바뀌므로 절대 캐시 경로를
  프로젝트 파일에 저장하지 않는다. 템플릿은 직접 읽고 결과 문서만 프로젝트에 쓴다.

## 프로필과 유효 설정

파이프라인을 시작하기 전에 `.harness/project.json`을 읽는다.
없거나 `status: draft`면 `skills/harness-init/SKILL.md`로 최초 설정 또는 인터뷰를 재개한다.
단독 조회·분석·리뷰는 init을 강제하지 않고 기본값으로 수행하며 사용한 전제를 밝힌다.
이미 ready이면 init 인터뷰를 반복하지 않는다.

설정 우선순위는 **기본값 < 프로젝트 settings < 작업 설정 < 사용자 명시 지시**다.
기본값은 `harness/defaults.json` 한 곳에만 정의한다. 문서의 수치 예시는 기본값의 예이며
판정은 항상 유효 설정을 따른다. 객체는 키별 병합, 배열은 전체 교체한다.
존재하지 않는 키·잘못된 타입은 기본값으로 무시하지 않고 오류로 보고한다.

Python 3.10 이상이 있으면 아래 보조 도구로 검증·병합한다. 이는 설치 프로그램이 아니다.
각 경로는 위 규칙으로 찾은 실제 절대 경로를 따옴표로 감싸 전달한다.

```text
python3 <plugin-root>/harness/bin/project.py check <project-root> --ready
python3 <plugin-root>/harness/bin/project.py resolve <project-root>
python3 <plugin-root>/harness/bin/project.py resolve <project-root> --task-config <task-settings.json> --override <user-settings.json>
```

작업·사용자 설정 파일은 `settings`의 내용과 같은 JSON 객체다. 명시 지시를 필요한
설정 키로만 변환한다. 기존 작업은 `effective-config.json`의 설정·프로필 해시·버전을
확인해 재개하며, 플러그인 업데이트만으로 진행 중 작업의 기준을 바꾸지 않는다.
신규 작업은 resolve 결과를 `_workspace/{slug}/effective-config.json`에 저장한다.
설정 변경이 필요한 재개에서는 변경 이유와 새 스냅샷을 기록한다.

Python이 없으면 `harness/project-profile.md`의 형식과 기본값을 읽어 같은 병합을 수행하고,
기계 검증은 미실행으로 명시한다. 검증기를 통과했다고 보고하지 않는다.

## 프로젝트 보완과 실행 범위

`.harness/context.md`와 `.harness/rules.md`, 프로필의 `extensions`에 등록된 파일을 읽는다.
추가 규칙·체크리스트·프로젝트별 절차는 이 파일들에 작성한다. 공통 스킬을 복제하지 않는다.
현재 사용자의 요청·상위 지침·프로젝트 기존 규칙을 우선하며, 충돌하면 구체적으로 보고한다.
`project.autonomy`는 운영 선호이며 배포·외부 메시지·권한 변경의 새로운 허가가 아니다.
이미 명시된 사용자 선택은 다시 승인받지 않는다. 미결정이 다음 작업에 영향을 줄 때만 묻는다.

프로젝트의 `test_commands`는 실제 설정에서 확인한 명령만 기록한다. resolve/check는
해당 명령을 실행하지 않는다. 테스트 요청 범위에서 실행하고 출력·종료 코드로 판정한다.
프로필에서 DDD 수준·필요 역할·추가 규칙을 선택할 수 있으며, 미적용 항목은 사유를 남긴다.

## 호스트와 위임

모드 선택과 별도로 실제 사용 가능한 기능·위임 권한을 확인한다.
Claude의 팀 API·모델명·에이전트 이름을 다른 호스트에 그대로 전달하지 않는다.
Claude 플러그인 에이전트는 `harness-sdlc:{role}`로 탐색하고, 다른 호스트에서는
`agents/{role}.md`를 읽어 역할 지침으로 전달한다. 사용 가능한 모델은 호스트 지침을 따른다.
위임이 불가능하거나 금지되면 skill 방식으로 수행하고 요청 모드와 실제 모드를 상태에 기록한다.
이는 작업의 품질 기준을 낮추는 근거가 아니다.

## 완료와 개선

G6는 승격 **후보**의 내용과 추적성을 검토한다. 승인된 문서를 승격한 뒤 반영 경로와
내용을 확인하고 작업을 완료한다. 사용자에게 이미 승인받은 범위는 재확인하지 않는다.
프로젝트 개선은 `.harness/`에 기록한다. 공통 개선은 제안으로 남기고 플러그인 소스 변경이
요청된 경우에만 소스 저장소에 반영한다. 설치된 플러그인 캐시를 수정하지 않는다.
